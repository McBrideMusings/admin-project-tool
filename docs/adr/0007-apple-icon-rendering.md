# ADR-0007: Apple (macOS + iOS) app-icon generation — alpha and Dock naming

`admin_lib.icons.generate_icons` always emits opaque RGB, flattening any alpha channel onto the background colour — there is no `opaque` flag, it's the only behaviour. macOS renders an icon full-bleed in the Dock only when it is fully opaque; any pixel with alpha below 255 anywhere (a soft shadow, an anti-aliased edge, a deliberate transparent margin) makes macOS render it inset instead. iOS masks icons into the rounded-rect shape and forbids alpha regardless, so the same flatten-to-RGB rule is correct there too.

The Dock hover tooltip and Finder read the `.app` filename, not `CFBundleName` or `CFBundleDisplayName` — a dev variant's Dock-visible name requires renaming the built `.app`, not just patching its Info.plist keys. `[apple] mac_dev_product_name` drives that rename; in-app strings should read `CFBundleDisplayName` from `Bundle.main` rather than a hardcoded name so the dev variant labels itself everywhere else.
