# ADR-0008: Command/action schema validation lives in `admin_lib/validate.py`

All "is this command/action well-formed" checks live in one module, behind `validate_command` / `validate_action_keys` / `validate_action`. The three pipeline sites that used to hand-roll these checks — `manifest.parse`, `archetypes.load_archetype`, and `archetypes._to_command` — delegate to it; after `validate_action` returns, `_to_command` only builds the `Command`, with no schema raises of its own.

`validate.py` defines `ValidationError` as an umbrella base; `ManifestError` and `ArchetypeError` are subclasses of it. `validate_*` functions raise the caller-supplied phase class via an injected `exc` argument (`ManifestError` at parse, `ArchetypeError` at resolve), and admin-run catches the single `ValidationError` base. `validate.py` owns the schema vocabulary and imports only `admin_lib/kinds`, never the parser or resolver, which is what lets `manifest.py` and `archetypes.py` call it without an import cycle.
