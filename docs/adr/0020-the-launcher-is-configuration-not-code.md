# ADR-0020: The launcher is configuration, not code

A project names the terminal it runs in with a `[terminal]` table of shell strings: `spawn`, `attach`, `kill`, and optional `status` and `read`. `spawn` runs with `ADMIN_CMD`, `ADMIN_LABEL` and `ADMIN_CWD` set, plus `ADMIN_ROW_*` on a row-bound dispatch (ADR-0018); its trimmed stdout is an opaque handle the tool stores and replays as `ADMIN_HANDLE`, never parses. `status` reports whether the pane still exists. `read` prints the pane's current text on stdout, run with `ADMIN_HANDLE` set (herdr: `herdr pane read "$ADMIN_HANDLE" --lines 40`); while a launcher-dispatched worker row is under the dashboard cursor, the Work tab reruns it on its tick and the live band shows the latest output as a snapshot, replaced whole each time and never appended. A launcher with no `read` shows "no local output - attach to see the real session" in the band. The tool names no launcher and opens no socket.

`locale` says where a dispatch runs, on an action, a multi-target target, or as the project default in `[terminal]`, and the most specific declaration wins. `window` sends the dispatch to that launcher from one surface: a dashboard row-enter. `hosted` runs it on a pty the dashboard owns and is what runs when nothing is declared. `inline` is not a value: `admin <command>` and `admin cmd` typed at a shell always run inline whatever the manifest declares, as does anything reached from inside an already-launched run. A workflow action's `locale` says where its workers run: `window` through the launcher, `hosted` on a dashboard pty running the claude command line, or inline one at a time when the workflow is run from a shell. With no `[terminal]` declared, every dispatch runs hosted.
